# Практика 13. Форматування таблиць за допомогою printf і дат

**Варіант 1 — база бібліотеки.** Використано той самий файл бази даних, що й у попередній практиці. Структура таблиць не змінювалася.

## Завдання 1

**Запит:**

```sql
SELECT id, title, copies_count AS raw_copies, printf('%d прим.', copies_count) AS formatted_copies FROM books ORDER BY id;
```

**Результат:**

| id | title | raw_copies | formatted_copies |
| --- | --- | --- | --- |
| 1 | Тигролови | 6 | 6 прим. |
| 2 | Кобзар | 4 | 4 прим. |
| 3 | Лісова пісня | 3 | 3 прим. |
| 4 | Місто | 2 | 2 прим. |
| 5 | Захар Беркут | 3 | 3 прим. |
| 6 | Чорна рада | 2 | 2 прим. |
| 7 | Кайдашева сім'я | 2 | 2 прим. |

## Завдання 2

```sql
SELECT id, title, copies_count, printf('%05d', copies_count) AS aligned_copies FROM books ORDER BY id;
```

## Завдання 3

**Запит:**

```sql
SELECT id, book_id, loan_date, date(loan_date, '+14 days') AS estimated_return_date, return_date AS actual_return_date FROM loans ORDER BY id;
```

**Результат:**

## Завдання 4

**Запит:**

```sql
SELECT strftime('%Y-%m', loan_date) AS loan_month, COUNT(*) AS loans_count FROM loans GROUP BY loan_month ORDER BY loan_month;
```

**Результат:**

| loan_month | loans_count |
| --- | --- |
| 2026-10 | 7 |

## Завдання 5

**Запит:**

```sql
SELECT 'not-a-date' AS input_value, date('not-a-date') AS date_result, strftime('%Y', 'not-a-date') AS year_result;
```

**Результат:**

| input_value | date_result | year_result |
| --- | --- | --- |
| not-a-date | NULL | NULL |

## Письмові пояснення

### Завдання 1

У таблиці `loans` немає числової колонки з ціною, сумою або кількістю. Тому відповідно до умови для варіанта 1 використано `books.copies_count`. Сирі значення — це числа `6`, `4`, `3` тощо. `printf('%d прим.', copies_count)` перетворює їх на читабельні підписи на кшталт `6 прим.`. Значення в таблиці не змінюються: форматування стосується лише результату запиту.

### Завдання 2

Специфікатор `%05d` задає мінімальну ширину поля у п'ять символів і доповнює коротші числа нулями зліва: наприклад, `6` стає `00006`. Це допомагає візуально вирівнювати числа у звітах, текстових вивантаженнях і при копіюванні результатів. У звичайному табличному інтерфейсі вирівнювання також робить значення легшими для порівняння.

### Завдання 3

Для кожної позики обчислено орієнтовну дату повернення як `loan_date + 14 days`. Це демонстраційний строк позики: бібліотекар може порівняти розраховану дату з фактичною `return_date`. Якщо `return_date` дорівнює `NULL`, це означає, що фактичну дату повернення ще не внесено. У цій роботі 14 днів — прийняте для прикладу правило, а не нове поле чи зміна даних.

### Завдання 4

Групування виконано за місяцем `strftime('%Y-%m', loan_date)`. Повна дата містить конкретний день, тому `GROUP BY loan_date` розділив би позики за окремими датами. `strftime()` приводить дати до спільного текстового ключа року й місяця, завдяки чому всі позики одного місяця потрапляють до однієї групи. У поточних даних усі 7 позик оформлено в жовтні 2026 року.

### Завдання 5

Для рядка `'not-a-date'` SQLite повертає `NULL` і для `date()`, і для `strftime('%Y', ...)`; SQL-помилка не виникає. Тому не можна вважати виклик функції дат автоматичною перевіркою введення: некоректне значення може пройти запит і дати `NULL`. Для надійного контролю потрібні окремі перевірки формату та допустимості дат, наприклад `CHECK`-умови, які перевіряють, що результат перетворення не є `NULL` і відповідає потрібному формату.

## Відповіді на контрольні питання

1. `printf()` форматує значення лише у вихідному наборі запиту. Воно не змінює фізичне значення `copies_count` у таблиці й не виконує `UPDATE`.
2. `strftime('%Y', ...)` повертає текст, оскільки `strftime()` формує рядок за шаблоном форматування. Для хронологічного сортування чотиризначний рік у форматі `YYYY` сортується лексикографічно так само, як числовий рік, але при арифметиці або числовому порівнянні його за потреби варто явно перетворити через `CAST(... AS INTEGER)`.
3. Оскільки некоректна дата дає `NULL`, саме лише використання `date()` або `strftime()` у `CHECK` не гарантує коректності. Обмеження має явно відхиляти значення, для якого перетворення повертає `NULL`, і за потреби перевіряти канонічний формат `YYYY-MM-DD`.

## Висновок

У практичній роботі застосовано `printf()` для читабельного форматування кількості примірників, `date()` для обчислення орієнтовної дати повернення та `strftime()` для групування позик за місяцем. Також перевірено поведінку SQLite на некоректному рядку дати: функції повертають `NULL`, а не помилку. Структуру бази даних і збережені значення не змінювали.
